WSL + VS Code：在 Windows 上搭一套顺手的 Linux 开发环境

发表于2026-11-15|更新于2026-11-15|技术
|浏览量:

想学 Linux又不想重装系统或忍受虚拟机的卡顿？WSL2 是目前 Windows 上最省心的答案：它跑的是真正的 Linux 内核，同时又能直接用 Windows 的显卡、剪贴板和文件系统。这篇文章从安装一路讲到用 VS Code 写代码，照着做大概 20 分钟能全部搞定。

为什么是 WSL2

方案 优点 代价
双系统 性能最接近原生 要重新分区，切换要重启，出问题容易全盘翻车
虚拟机 隔离干净，可快照 图形界面卡顿，吃内存，GPU 直通配置麻烦
WSL2 真 Linux 内核、启动秒开、文件互通、VS Code 直连 没有完整桌面（但可跑 WSLg 图形程序）

WSL2 本质是一个轻量虚拟机，但微软把宿主机集成做到了极致：localhost 端口互通、剪贴板共享、/mnt/c 直接挂载 C 盘、图形程序能弹窗。对绝大多数开发场景（包括 ROS 2、PX4、深度学习），它和原生 Ubuntu 的差距已经很小。

一、安装前的检查

项目 要求
系统版本 Windows 11，或 Windows 10 版本 2004（内部版本 19041）及以上
虚拟化 BIOS 中开启 VT-x / AMD-V（绝大多数机器默认开启）
磁盘空间 至少 30 GB 空闲；装完 ROS 和一堆依赖后 50 GB 更稳妥
网络 安装过程需要下载内核与发行版，建议提前准备好代理

确认系统版本：Win + R 输入 winver。确认虚拟化：打开任务管理器 → 性能 → CPU，右下角应有「虚拟化：已启用」。

四、让它变得好用：两份配置文件

WSL 的行为由两份文件控制，改完都要 wsl --shutdown 再重新启动才生效。

1. %USERPROFILE%\.wslconfig —— 全局配置（Windows 侧）

在文件资源管理器地址栏输入 %USERPROFILE% 回车，新建文件 .wslconfig（注意前面的点，用记事本保存时选「所有文件」以免变成 .txt）：

配置项 作用
memory / processors 限制 WSL 占用，避免把宿主机的内存吃光（默认最多可占一半物理内存）
networkingMode=mirrored 镜像网络，WSL 与 Windows 共享 IP，局域网内其他设备可直接访问 WSL 服务
dnsTunneling 通过 Windows 隧道解析 DNS，解决换网络后 WSL 上不了网的老问题
autoProxy 自动继承 Windows 的系统代理，省掉在 .bashrc 里手写 http_proxy

六、用 VS Code 连接 WSL

命令行编辑器（nano、vim）改配置文件很高效，但写几百行代码就力不从心了。VS Code 的 Remote 模式能让你在 Windows 上用图形界面编辑 Linux 里的文件，终端、调试器、扩展全部跑在 Linux 侧，文件名、权限、路径都是原生 Linux 的。

1. 安装两个东西

  • Windows 侧安装 VS Code（安装时勾选「添加到 PATH」）。
  • 在 VS Code 扩展市场搜索 WSL（ms-vscode-remote.remote-wsl）并安装。这一步只需在 Windows 侧做。

七、常用命令速查

在 PowerShell / CMD 中使用：

命令 作用
wsl -l -v 列出所有发行版及运行状态、WSL 版本
wsl -d Ubuntu-24.04 启动指定发行版
wsl -t Ubuntu-24.04 终止某个发行版
wsl --shutdown 关闭所有 WSL 实例（改完配置后用）
wsl --update 更新 WSL 内核与本体
wsl --set-default Ubuntu-24.04 设置默认发行版
wsl --export Ubuntu-24.04 D:\backup.tar 导出整个系统做备份
wsl --import Ubuntu-backup D:\WSL\backup D:\backup.tar 从备份恢复
wsl --manage Ubuntu-24.04 --move D:\WSL\Ubuntu 把发行版整体迁移到其他盘（WSL 2.0+）
wsl --unregister Ubuntu-24.04 注销并删除该发行版（不可恢复，慎用）

在 WSL 内部：cd、ls -a、pwd、cat、sudo、exit。多练 Tab 补全，比手打快得多，也能少打错字。

八、常见问题

安装时报 0x80370102：虚拟化没开。进 BIOS 打开 Intel VT-x / AMD-V，若开着仍报错，检查是否被 Hyper-V 之外的虚拟化软件（如旧版 VMware、部分杀软）占用。

卡在下载，或商店一直转圈：加 --web-download；仍然慢就挂代理，或先 wsl --update 再重试。

WSL 里能 ping IP 但域名解析失败：多半是 DNS 配置被覆盖。.wslconfig 里加 dnsTunneling=true，然后 wsl --shutdown。旧方案是手写 /etc/resolv.conf 并加 chattr +i 锁死，但不推荐——换网络后又会失效。

端口在 Windows 上访问不到：WSL2 默认会把 localhost 转发到 Windows，直接访问 localhost:端口 即可。若用了镜像网络，则按 WSL 的 IP 访问，注意 Windows 防火墙放行。

磁盘占用越来越大：WSL 的虚拟磁盘只增不减。可以在 PowerShell 里压缩（先 wsl --shutdown）：

该命令需要 Hyper-V 组件；家庭版可用 diskpart 的 compact vdisk 替代。更省事的办法是直接用 wsl --manage <发行版> --move 换盘。

系统时间不对：WSL 与 Windows 时间同步偶有偏差，在 WSL 里执行 sudo hwclock -s 校正。

中文显示成方块或在终端乱码：Windows Terminal 默认已支持 UTF-8，确保 locale 输出含 zh_CN.UTF-8 或 en_US.UTF-8；缺失时执行 sudo apt install -y locales && sudo locale-gen。

code 命令找不到：关闭所有 VS Code 窗口，在 PowerShell 里 wsl --shutdown，重新进入发行版执行一次 code .，WSL 扩展会重新写入 PATH。仍不行就检查 Windows 侧 WSL 扩展是否已启用。

检查清单

装完之后，下面几条都能通过，说明环境已经可以开始干活了：

  • wsl -l -v 显示发行版状态为 Running，VERSION 为 2
  • sudo apt update 能走国内镜像，几秒内完成
  • wsl --shutdown 后重进，systemctl status 正常工作
  • 在 ~ 下执行 code . 能打开 VS Code，左下角显示 WSL: Ubuntu-24.04
  • VS Code 内置终端里的 gcc --version 有输出（说明扩展和工具链都在 Linux 侧）
  • 浏览器能访问 WSL 里跑起来的服务，例如 python3 -m http.server 8000
  • 知道代码该放 ~ 而不是 /mnt/c，并且已经这么做了

环境搭好只是起点。接下来该熟悉的是 shell、包管理、权限这些每天都要用的东西——命令行的门槛在前两周，过了之后就再也不想回去了。
